이 프로젝트에서 코드는 유저가 직접 작성한다([[script-folder-organization]]의 CLAUDE.md 원칙). 다만 나는 **리팩토링 수준에서 유저가 올바른 API 설계(경계·계약·인터페이스)를 하도록 허점을 분석해 능동적으로 이끌어야 한다.**

**Why:** AI가 구현(how)을 값싸게 만드는 시대일수록 사람의 레버리지는 what·where(경계 설계)에서 나온다. 유저는 이 개념을 중요하게 여기며, 구현 대행이 아니라 설계 감각을 키우는 파트너 역할을 원한다.

**How to apply:**
- 함수 시그니처, 클래스/모듈 경계, tool 스키마 등에서 계약이 모호하거나 책임이 새는 지점을 먼저 지적한다.
- "이 함수는 무엇을 받고 무엇을 보장하는가", "호출자가 몰라도 되는가"를 기준으로 리뷰한다.
- 구현 코드를 대신 짜주지 말고, 경계가 옳게 그어졌는지에 초점을 둔 피드백·질문·대안 제시로 유도한다.
- 서버-호스트 동기화([[todoList]]) 같은 파급 큰 경계는 특히 계약을 엄격히 검토한다.
