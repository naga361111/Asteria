콘텐츠 드로어 드래그앤드롭이 비효율적이라, 서바이벌 크래프팅 게임(발하임/러스트류) 빌드 모드처럼 에디터에서 레벨디자인을 하게 하는 전용 툴을 만들기로 확정. **지금은 PCG 전 단계** — 배치 툴부터.

**빌드 모드 = 5개 기계요소:** (1) 팔레트에서 피스 선택 (2) 고스트 프리뷰가 커서 추종 (3) 그리드/소켓 스냅 (4) 회전·검증(초록/빨강) (5) 클릭 연타 배치.

**언리얼 확장점 = Editor Mode(UEdMode)가 척추.** Scriptable Tools 대신 C++ UEdMode로 직행 확정(2026-09-13). `Source/AsteriaEditor` 에디터 모듈 + `UAsteriaBuildEdMode`(ID `EM_AsteriaBuild`) + `UAsteriaPlacePieceTool`까지 구현 완료 (2026-09-13). 요소 (2)(3)(5) 동작, 제거까지. 남은 건 (1)팔레트·(4)검증.

## 구현하며 확정된 것

**Z는 절대 연속 좌표의 반올림에서 뽑지 않는다.** 가장 비싸게 배운 함정. `GridSnap(Hit.ImpactPoint.Z, 층고)`는 표면이 평평할 때 Z가 **상수**인데 그 상수가 반올림 타이(층고/2)에 앉으면 부동소수 잡음만으로 층이 위아래로 진동한다. 피스 피벗이 가운데면 정확히 이 상황이 된다. → 윗면은 **맞은 액터의 배치 Z**(액터당 상수)에서, 옆면은 **커서 높이**(커서 따라 변하므로 경계 통과가 의도된 조작)에서 뽑는다. 판별 기준은 `ImpactNormal.Z`.

**층 칸은 맞은 피스의 `Bounds.Min.Z`에서 센다.** `GroundPlaneZ` 기준으로 세면 피벗이 가운데인 피스에서 층 구간이 반 칸 어긋나 "3층 아래쪽을 가리켰는데 2층에 생성"이 난다. 바닥 기준이면 피벗 위치와 무관하고 여러 층짜리 피스의 중간 층도 잡힌다.

**옆면 배치는 법선 방향으로 반 칸 + 앱실론 밀어낸 뒤 스냅.** 안 밀면 맞은 블럭과 같은 칸으로 반올림돼 겹친다. 앱실론은 벽면이 격자선 위에 정확히 놓인 경우(피벗이 모서리) 타이 진동을 막는다.

**고스트는 전용 반투명 머티리얼을 덮어씌운다. 원본 머티리얼을 반투명화하는 건 불가능하다** — 블렌드 모드는 셰이더 퍼뮤테이션이라 MID로 못 바꾸고, MIC `BasePropertyOverrides`에는 **Opacity 오버라이드 자체가 없어서** 블렌드 모드만 뒤집어도 알파 1로 그려진다. 게다가 정적 퍼뮤테이션 재컴파일을 유발한다. 지금은 엔진의 `M_SimpleUnlitTranslucent`(`Color` 파라미터) 사용. **[[hearthvale-modular-kit-pcg]] 키트가 단일 마스터 머티리얼로 정리되면** 그때만 "마스터를 Translucent로 복제 + GhostOpacity 스칼라" 방식으로 올라갈 수 있다. 그 전엔 불가능.

**툴은 하나, 모드 전환은 Shift 모디파이어.** 제거는 Foliage 페인터 관례대로 Shift+클릭. 별도 툴로 나누면 `FUICommandInfo` 팔레트 세트가 필요해지는데 얻는 게 없다 — **툴이 3개째 되는 시점에** TCommands + `UEdMode::RegisterTool`로 갈아탄다. 지금은 `RegisterToolType` + `StartTool` 직행.

## 경계

**에디터 오서링 툴이라 프로젝트 핵심 불변조건(서버 권위→클라 동기화)이 적용 안 됨** — 결과물은 에디터 타임 스태틱 지오메트리, 복제 경로 밖. 런타임 건설과 혼동해 복제 계약 끌고 들어오지 말 것. 잡을 경계 셋 = 피스 정의 데이터(에셋) ↔ 배치 툴(에디터 모듈) ↔ 스폰된 액터.

스냅 계산은 `AsteriaGridSnap.h`의 순수 함수 하나에만 있다 — 고스트와 실제 배치가 갈라지면 프리뷰가 거짓말을 한다. **소켓 스냅(2단계)이 갈아끼울 이음매가 여기다.**

## 다음 미결

- **피스 카탈로그 데이터 형태(DataAsset vs DataTable) 아직 미정.** 지금은 툴 프로퍼티의 `UStaticMesh` 한 칸이 팔레트 역할. 회전·소켓·변형이 실제로 뭐가 필요한지 본 뒤에 정하기로 함.
- **검증(초록/빨강)과 지지 규칙은 피스 정의에 높이·타입이 들어간 뒤에야 제대로 된다.** "바닥 슬래브 윗면=같은 층 / 벽 윗면=다음 층"을 지금은 바운즈 높이로 추정 중인데, 이건 근사다. `PreviewMaterial` 슬롯이 검증 머티리얼 자리를 그대로 받는다.
- 소켓 스냅은 여전히 2단계. [[hearthvale-modular-kit-pcg]]의 개구부·계단 구속조건이 정확히 소켓 정합 문제.

**Why:** 구현이 값싼 시대에 사용자 레버리지는 경계 설계(what/where)에 있고, 이 툴의 경계는 데이터/에디터모듈/액터 3분할 + 스냅 모델 선택.
